# KLIPY library

The custom iOS picker searches KLIPY memes and GIFs, previews a selection, then attaches it to a draft. Posting or sending is a separate action. The custom caption meme composer remains available.

## Local setup

Create a **mobile app key** at https://partner.klipy.com (API Keys → Create your platform). Save it directly in `MaroonSocial/Resources/Klipy.json` as `{"appKey":"…"}`. That file is gitignored; `Klipy.example.json` documents its shape. Do not paste keys into issue text or logs. Regenerate the Xcode project and rebuild after first creating the file. The mobile API key is intentionally bundled in the app, as required by KLIPY's direct-client integration; it is not a privileged backend credential.

An absent/empty/malformed key shows an honest unavailable picker. UI fixture mode always disables provider requests regardless of whether a developer has installed a key. Testing keys are limited to 100 API requests/hour; request Production access in the Partner Panel after completing integration review.

## Delivery and privacy

Official standard terms require direct client API/media requests and preservation of original URLs. We store **references only** in the private attachment table. No KLIPY image bytes are uploaded to Supabase Storage, reencoded, mirrored, or kept in an app disk cache. URLs/query strings are unchanged. Media is fetched using an ephemeral URLSession, every redirect must remain HTTPS on `static.klipy.com`, `static1.klipy.com`, or `static2.klipy.com`, and reads stop at 5 MB. ImageIO validates JPEG/PNG/GIF, up to 80 frames, 15 seconds and 12 million decoded pixels. Unsupported results retain their position and explain unavailable previews.

Attachment references inherit existing accepted-room/post permissions. A recipient cannot read an unsent draft. Leaving/blocking/deleting revokes reads through existing server authorization. Account deletion deletes references without placing nonexistent provider files in our Storage cleanup queue. Public posts are readable according to their community's membership rules; a provider URL obtained by an authorized reader is naturally a provider-hosted URL, not a secret signed Storage URL.

Searches/media expose ordinary client network data to KLIPY. `customer_id` is a separate random installation ID; we never send the app's account ID, username, email, social credential, or IDFA. A successful user send/post sends the provider's share event. Selection alone does not. No fabricated moderation reports or ad clicks are generated by tests.

## Advertisements

Provider ad objects keep their returned order in the picker. The unmodified HTML is rendered in a full-width nonpersistent WKWebView at the returned height, labeled Advertisement · KLIPY. It has no native bridge or community credentials, denies camera/microphone requests, and scrolls with results. Explicit HTTPS link taps open the system browser; scripts cannot automatically replace the main document. Layout hints request up to the device width and 250 px height; the app does not enable a Partner Panel monetization setting or invent fill/earnings. No AdMob SDK or feed monetization is installed by this feature.

## Picker and memory use

The picker uses a black, image-led two-column masonry layout, with natural media proportions and an upper bound for unusually tall provider dimensions. Compact Memes/GIFs/Recents tabs and search stay above the results. Ads returned by KLIPY remain unchanged and retain their ordered position as scrollable full-width rows; there are no forced interstitials. A separate preview loads the full rendition and requires an explicit Attach action; opening a preview never sends or posts media.

Grid cells fetch the provider's small preview rendition, decode only the first frame (maximum 480 pixels), and keep a strict 24 MiB / 64 bitmap memory LRU. At most 4 thumbnail jobs run simultaneously; duplicate visible URLs share a request and an unused request is cancelled. No media is saved to a persistent thumbnail cache. The selected preview animates unless Reduce Motion is enabled. Recent picks store at most 30 validated references, not downloaded images or search text, on this device only. Clear recents has a confirmation; cancelling it leaves both history and the unsent draft intact.

Offline UI fixtures require both `--uitesting` and `--uitesting-klipy` in a DEBUG build. They use generated local PNG/GIF data, an isolated in-memory history, and no provider API key. Tests cover natural portrait/landscape sizing, search, GIF animation selection, back/cancel, attachment confirmation, Recent picks and clear/cancel. A separate native WebKit test exercises actual ad HTML navigation restrictions.
